# Workspace instructions

Start with the user's focus. Read WORKSPACE.md and only the relevant source route or existing task handoff. With no focus, ask for the task after reading the entry point. A known-file edit does not require a broad orientation.

Linked sources do not expand the authorized change scope. Preserve explicit scope corrections on continuation.

Read the selected repository's applicable instructions and resolve its real path, branch and changes before working. Preserve modified checkouts. Fetch current upstream before mutable status analysis when available; do not reset, stash or pull another task's changes. Use an isolated branch/worktree for repository changes under the configured policy.

Keep approved intent, observed implementation, deployment, measured results and proposed changes separate. Prefer primary evidence with material dates/revisions. A tracker state or empty search alone does not establish delivery, absence or ownership. Do not invent targets, commitments or stakeholder approval.

Preserve meaningful manual edits. Use stable record identities after rows or files move. One source owns each fact; linked documents and websites are derived views. Keep private configuration and conversations in authorized private locations. A directory named working or sandbox is not an access control.

Use connected, authorized tools and the correct account. Do not change authentication, install dependencies, start services, refresh datasets or alter global configuration merely to read context. Follow the user's policy for external writes, diff review, pushing, publishing and merging; approval for one action does not authorize another.

Keep reusable setup separate from machine-local source bindings and private content. Reproducing the setup does not authorize importing documents, datasets, account state or history. Any private-repository backup is a separate owner decision, not a framework prerequisite.

Verify consequential behavior and actual artifact layout/content placement where relevant. Report what was checked and what remains uncertain. For substantial work, update the handoff section in the existing working document: goal/completion condition; decisions/provenance; branch/review; evidence/dates; open questions; next action. A handoff does not confer approval.

Write for the reader's decision with descriptive headings and concise concrete language. Present meaningful content before IDs; retain source references for traceability.
