# Fictional journey: reconcile a scheduled-export request

All records, people and behavior here are independently fictional. This is a worked example, not a report of an actual agent run.

## Task and sources

The owner asks for a comparison they can review before selecting scope. The permitted output is a local proposal; changing the workbook, tracker, linked repositories or shared site is outside this stage.

| Source | Recorded content | Authority |
| --- | --- | --- |
| Customer request | Schedule an export and send it to a team folder | Requested need, not accepted scope |
| Owner's planning workbook | Explore scheduling; no build commitment | Accepted scope decision |
| Delivery ticket | Scheduled exports marked complete | Tracker state needing reconciliation |
| Inspected contract | Personal on-demand exports exist; scheduling is not in the inspected API | Implementation at that revision only |

## First pass and owner correction

A first draft incorrectly treats the completed ticket as approval to publish scheduled-export support. The owner clarifies that the ticket covered an earlier on-demand export and that the workbook still accepts discovery only.

The corrected proposal preserves both source records and separates the independently reviewable outcomes:

| Outcome | Current evidence | Proposed next step | Decision status |
| --- | --- | --- | --- |
| Reuse on-demand exports | Present in the inspected contract | Check rollout before making a universal availability claim | Verification needed |
| Schedule exports | No path in the declared inspection scope | Validate the need and inspect other relevant paths | Discovery accepted; build uncommitted |
| Send exports to a shared folder | Requested; access and destination behavior unknown | Investigate privacy and integration constraints | Not accepted scope |

The proposal links the existing ticket rather than duplicating its estimate. The workbook continues to own scope; the tracker owns its own delivery status. A derived summary does not overwrite either.

## Verify and hand off

Check that every requested outcome has a disposition, source links resolve, manual workbook decisions remain unchanged, and no proposed capability is labelled supported. No external write is needed to complete this review stage.

Handoff: the comparison is ready; scheduling discovery is the accepted decision; build commitment and shared-folder constraints remain open. The next session reads this handoff and the current workbook, then prepares discovery questions. It does not create tickets, edit linked repositories or infer publication approval.
