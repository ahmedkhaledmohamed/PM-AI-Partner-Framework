# Record the contribution

Use the visible task context, accepted decisions and actual diff. Summarize problem framing, approach, key decisions, pivots and outcome where applicable, with one to three sentences per section. Omit empty sections. Be factual and proportionate; do not manufacture a large contribution from a small edit.

Paraphrase rather than quote prompts. Do not include transcripts, session identifiers, credentials, private account details, personal machine paths or internal hostnames. Use an immutable dated filename such as `.thinking/YYYY-MM-DD-topic.md` when a repository record is requested. Do not overwrite an older trail or automatically stage/publish it.

If an approved extractor is needed, run it only within the authorized context. The bundled legacy helper can read Claude session files locally with an explicit extraction flag; it does not support every runtime. Distinguish missing/unreadable sessions from a successful extraction with zero matching records. Use a manual sanitized account of visible context when appropriate and disclose that method. Keep any temporary extracted material outside repositories in authorized private storage.

Show the record and relevant diff for review under the target policy before committing, posting or sharing. A contribution record documents the work; it does not approve a commit, merge or release. Recheck the actual revision before making claims about the result.
