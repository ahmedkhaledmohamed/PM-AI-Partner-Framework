# Route planning work
Resolve the planning cycle and its canonical templates, glossary, and guidance. Do not reuse historical cycle rules as current policy.
Discover available planning tools and their actual schemas before rebuilding a workflow. Prefer maintained review, drafting, submission, synchronization, migration, and ownership-discovery capabilities when they cover the request.
Distinguish reading, proposals, and writes. Status or analysis requests do not authorize changing scope, commitments, owners, or records.
If a specialized tool is unavailable, use authorized read-only sources and report capability gaps. Do not invent tool names or assume an agent role exists.
For inventories, declare filters and complete pagination. Verify period and organization semantics; distinguish tagging, requested contribution, and confirmed commitment.
Use the authorized account for each source. Do not substitute cached personal credentials for organization-controlled access.
Before an authorized synchronization, present the concrete changes and unresolved mappings for review. Preserve original cycle history and stable IDs.

Keep enduring workstreams and success measures separate from cycle-specific priorities or sponsorship. A priority is a way to fund work, not a capability taxonomy. One deliverable can contribute to several completion criteria; preserve those links without duplicating work or estimates. Describe proposed scope before requesting a decision, using current evidence rather than an empty question. An alignment can be consultation, routine support, development or discovery; agreement to collaborate does not establish a build commitment.
