# Select task context

Parse the focus and requested output before reading background. Reading workspace context is a way to begin the named task, not a separate requirement to brief the user on every project.

## Locate the work

- With no focus, read the current workspace entry point and ask for the task. Do not inventory repositories or select an old task.
- For a new focus, identify the goal, completion condition and relevant repository/source route. A known-file change can start with that file and its applicable instructions.
- For continuation, read the named task's existing working document or handoff and branch/review record. Recover decisions and remaining work without reconstructing unrelated history.

Discovering a linked repository or source does not authorize changing it. Keep the selected task scope through repository switches and continuation.

Resolve the current directory, real repository root and branch/worktree. Symlinks and nested checkouts can cross instruction boundaries. Read applicable instructions before working in another repository; changing directory does not necessarily reload the runtime's original instructions.

Use a maintained WORKSPACE.md or README and any available workspace map to select a route. These are project conventions, not universally automatic instruction files. When a path is missing or stale, check an existing source map before widening a search. Do not recursively inventory all projects or turn a legacy README into a background briefing.

## Select evidence

Give each source its actual authority: human decisions for accepted scope; current tracker records for tracking state; approved documents for intent; inspected code/contracts for implementation; primary datasets for measured behavior. A local export or generated summary is a dated pointer. Check revisions and material retrieval dates, and report conflicts.

Before relying on mutable repository status, fetch the target upstream branch and compare revisions when access allows. Preserve changed checkouts; do not pull, reset or stash another task's work. Scope search to the selected topic/repository. Use available specialist skills and connected tools; do not assume configured connectors work or load every reference.

Do not start services, refresh datasets, change authentication or rebuild indexes merely to orient. An empty search does not establish missing behavior or ownership.

## Continue and hand off

Briefly state the goal, selected working document/repository, relevant sources and next action. Continue within existing approvals. Startup is not a reason to request an already granted approval again; a handoff is not permission for a new action.

For substantial ongoing work, maintain a concise section in the existing working document: completion condition; accepted decisions and provenance; branch/review; sources and dates; open questions; next action. Link evidence instead of copying transcripts. Create another file only when no suitable working document exists. Keep private configuration and context in their authorized location.
